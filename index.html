What it checks

  • envgate check — primary command
  • Missing keys vs example → errors
  • Extra keys → warnings by default; errors with --strict-extra
  • Placeholder / empty detection (TODO, CHANGEME, your_*, replace_me, empty)
  • High-confidence secret pattern kinds: GitHub token, AWS access key ID, Stripe live secret key, Slack token, private key blocks
  • Redacted output (Value redacted / [REDACTED] — never prints secret values)
  • --env, --example, --json, --strict-extra
  • Exit codes: 0 pass, 1 violations, 2 usage/missing file
  • Zero runtime dependencies; Node 18+
  • Examples directory (synthetic demos only)
  • Sample GitHub Actions workflow sketch
  • Full MIT source (bin/, src/, tests, LICENSE, README)

Requirements

  • Node.js 18+
  • Ability to run a local CLI (macOS, Linux, or Windows with Node)
  • An .env.example (or path passed via --example) for meaningful checks

GitHub Actions example

From the bundled workflow sketch. Provide .env in CI from secrets/vars — do not commit real secrets. EnvGate only reads the env/example paths you pass — it does not scan the whole repository.

.github/workflows/envgate-example.yml 
# Example only — not published. Copy into a consuming repository.
# Runs EnvGate as a CI gate before tests/deploy.
name: EnvGate

on:
  push:
    branches: [main, master]
  pull_request:

jobs:
  envgate:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: "22"

      # When published to npm, prefer: npm install -g envgate
      # For local/path installs during development:
      - name: Install EnvGate
        run: npm install -g .

      # Provide CI secrets via the runner environment or a generated .env
      - name: Write .env from GitHub Secrets (example)
        run: |
          cat > .env <<ENV
          APP_NAME=${{ vars.APP_NAME }}
          NODE_ENV=production
          PORT=3000
          DATABASE_URL=${{ secrets.DATABASE_URL }}
          API_KEY=${{ secrets.API_KEY }}
          ENV

      - name: Run EnvGate
        run: envgate check --strict-extra

      # Optional: machine-readable report
      # - name: EnvGate JSON
      #   run: envgate check --json > envgate-report.json

Honest limits

Honest limits: EnvGate is a gate/check, not a security guarantee. It does not scan your whole repo or git history, does not implement --schema, and does not replace a dedicated secrets scanner.

Exact limitations

  • Checks only the env/example paths you pass — not the whole repository
  • Secret detection is high-confidence and narrow, not exhaustive
  • Parsing is intentionally simple (see README “Parsing support & limitations”)
  • --schema is not available in 0.1.0
  • MIT license means recipients may use, modify, and redistribute under MIT terms; this sale does not grant proprietary exclusivity
  • This is a check helper, not a warranty of security or compliance

Not included / not claimed

  • --schema / typed JSON schema validation (not implemented; CLI exits with a clear “not supported” message if passed)
  • Multiline values, $VAR / ${VAR} expansion, escape sequences in quotes
  • Whole-repo or git-history scanning
  • License-key / DRM gating inside the binary
  • Guaranteed catch-all for every secret format
  • Promised support SLAs or release dates

FAQ

What does EnvGate actually do?

EnvGate is a local Node.js CLI you run against your .env and .env.example. It reports missing keys, placeholder/empty values, optional extra-key warnings, and a focused set of token/key patterns. Findings name the key and kind only; values stay redacted.

Is --schema supported?

--schema is not available in 0.1.0. Typed / JSON schema validation is not implemented; the CLI exits with a clear “not supported” message if passed. Schema validation is future work, with no promised ship date.

Does it scan my whole repository or git history?

No. Checks only the env/example paths you pass — not the whole repository. It does not scan arbitrary files or git history, and it does not replace a dedicated secrets scanner. Secret detection is high-confidence and narrow, not exhaustive.

Will EnvGate print my secrets?

Secret values are never printed. Findings name the key and kind only. Redacted output uses Value redacted / [REDACTED].
